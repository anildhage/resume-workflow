# FastAPI Change Management Process

**Organization:** Societe Generale Investment Banking  
**Period:** 01/2025 - 03/2026  
**Role:** Application developer / automation developer

## Business context
- The weekly release process relied on a third-party change-management platform that required repetitive manual navigation and multiple steps for routine actions.
- The workstream aimed to improve release efficiency without replacing the governing process or platform.

## Problem or objective
- The existing process created manual effort and slowed production delivery for approved changes.
- The objective was to automate only the repetitive formalities while preserving the required control flow and compliance steps.

## Responsibilities and contributions
- Identified repetitive manual steps suitable for automation.
- Designed a lightweight FastAPI service around the essential weekly release operations.
- Implemented API endpoints and integrated with the third-party change-management API.
- Validated the workflow against business-request requirements.
- Supported testing and production-readiness checks.

## Tools, platforms, and systems
- Python
- FastAPI
- REST API integration
- Backend service development
- Change-management workflow automation

## Outcomes and value
- Reduced time spent on weekly release formalities.
- Reduced repetitive navigation and manual interaction.
- Enabled faster delivery of approved changes to production.
- Improved repeatability and consistency in the release workflow.
- Created a focused internal service instead of depending on the full third-party UI for routine actions.

## Evidence or summary
- “I built a FastAPI service that integrated with our third-party change-management API and automated the essential steps in the weekly release process. The goal was not to replace the platform, but to remove repetitive manual navigation from routine release activities. This shortened the release workflow and helped the team move approved changes to production faster.”
